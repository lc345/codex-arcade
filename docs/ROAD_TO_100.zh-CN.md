# 一百款路线：退役、补齐与发布

截至 0.11.1-beta.1：原 100 款删除旧 26 款，再增加[险境十局](GAUNTLET_TEN.zh-CN.md)、[不服再来](HARDCORE_TEN.zh-CN.md)和[极限六式](EXTREME_SIX.zh-CN.md)，**95 款编译包与 5 款引擎页面，共 100 款不同作品，均已接入任务小窗**。默认从全部 100 款轮换，精选模式仍为 7 款，两者不能相加。93 款仍标 preview，不能把 100 称为全部已正式验收。五个引擎页面是 `godot-junk`、`cart-downhill`、`reel-break`、`last-beacon`、`grab-go`。见[按唯一 ID 生成的当前清单](PLAYABLE_INVENTORY.zh-CN.md)。

目标不是凑满数量，而是到发布时有 100 款无需读长教程、能迅速参与、能安全随任务停止的作品。当前不喜欢或操作复杂的作品应返工或归档；一旦剔除，净数量必须如实减少。

## 按批验收

上一批五款：翻锅大师、一杆清台、纸上狂飙、瓶盖入杯、折纸穿风。

前一批十款：[运动与机关](SPORTS_TEN.zh-CN.md)，用户反馈整体可玩，球类暂时足够，多米诺过桥仍不容易理解，列入返工候选。

上一批十款：[十种奇妙小差事](ODD_TEN.zh-CN.md)，用户反馈整体可以，但有些有意思、有些无聊；还不能把整批当成已认可的正式作品。

上一批十款：[十种挑战，十种手感](CHALLENGE_TEN.zh-CN.md)，包括过街、钻地、激光穿行、暗桥记忆、切玻璃、单向转弯、冻结机关、天平装货、路口调度和转盾格挡。用户反馈整批不错、有意思。

此前十款：[百款新章](CENTURY_TEN.zh-CN.md)，转向调色、圈选捕获、画轨道通车、有限步消除、维修、局部旋转、辨伪、装箱、解结与影子观察。此前达到 100 只是历史数量里程碑，旧 26 款已按要求删除。

上一批十款：[险境十局](GAUNTLET_TEN.zh-CN.md)，强调预测、惯性平衡、镜像控制、推箱死角、数字推理、划线占地、折叠、切分节奏与气压调节。用户反馈仍然偏简单。

上一批十款：[不服再来](HARDCORE_TEN.zh-CN.md)，研究经典高难游戏后，加入不可修正的出手、连续单命挑战、间接惯性操控、杆尖碰撞、不可逆路线及反向记忆。用户已试玩，反馈其中三四款很有挑战性，能激起挑战欲望；没有逐一指定是哪几款，默认池暂不擅自扩充。

本批六款：[极限六式](EXTREME_SIX.zh-CN.md)，全部聚焦精密操作：持续控线、贴壁蓄力反蹬、双核旋转穿障、瞄准穿闸冲刺、定时点击与曲线拖拽、后坐力对冲刹车。每款三关、一错重试当前关，不使用隐藏陷阱或随机不可解布局。完成后转向全库筛选与发行收尾，不默认继续堆数量。

每批按同一流程走：

1. 每批五到十个一句话原型，各自只有一种主要操作，明确输赢与快重试。
2. 先做规则和真实碰撞回放，再独立设计美术、镜头、角色动作和声音。
3. 每款至少三段递进挑战；换颜色或关卡不算新游戏。
4. 接入统一包、停止/恢复、键盘/触屏、静音及减少动效。
5. 桌面和窄屏实际交互验收，人工试玩后决定保留、返工或归档。
6. 通过后加入官方可玩计数与合适的随机池，更新素材许可和记录。

## 后续方向

这些是候选，不是已实现游戏或固定排期。

| 批次方向 | 候选玩法 | 与现有作品的差异 |
| --- | --- | --- |
| 碰撞连锁 | 多米诺、玻璃拆墙、弹珠机关、货架倾倒、气球挤压 | 一次输入带来长反馈，强调破坏和连锁 |
| 节奏时机 | 切片、击球、旋转开锁、节拍格挡、接力传盘 | 不依赖角色左右移动，节奏差异清晰 |
| 单键冒险 | 墙间弹跳、地铁冲门、滑索换轨、滑冰刹车、吊桥过河 | 快速失败重试、分支与路线选择 |
| 轻策略 | 极简塔防、三张牌对战、连锁合成、推箱变形、有限步消除 | 一次只需做一个选择，不堆按钮 |
| 喜剧物理 | 搬家、电梯超载、软体摔跤、餐盘杂技、磁铁脱困 | 失败本身有趣，目标清楚 |
| 不同镜头 | 第一人称投掷、横版剪影、等距玩具、像素街机、定格黏土 | 摄影和资产真正改变，不靠调色换皮 |

## 发布前的收尾

- 统一接入有价值的独立试玩，剔除用户已否定且未返工的内容；审核“100 可玩”清单。
- 做可搜索的游戏目录和社区贡献模板；标签包含控制复杂度、局长、引擎、静音体验、风格及作者。
- 真机验证安装、升级、卸载，尤其 Codex 任务开始/完成、异常中断、刷新与更新后的恢复。
- 审核全部素材许可证、体积、依赖及运行时网络行为。无来源音乐、商业游戏素材、品牌角色不进入发行包。
- 排除 `output/`、个人配置、日志、模型内容、密钥和本机专属路径，检查 GitHub Actions 与 Release 校验和。
- 为社区保留 reviewed game pack 路径；任何 JavaScript 必须审查，不把 Shadow DOM 当成沙箱。声明式场景与视频许可独立校验。
- 本地视频/社区短片作为后续可选内容类型，不能访问 Agent 数据或改变任务状态；本批不恢复已隐藏的视频入口。

达到质量门槛并确认公开范围后，才创建/推送 GitHub 仓库与 Release。这份路线图不自动发布项目、不自动下载或执行社区代码。
