# 从本机到 GitHub

## 用户只做三步

1. 安装、打开并登录 Codex Desktop。
2. 从 GitHub 仓库右侧 Releases 下载 **Agent-Stage-for-Codex.zip**，双击解压。不要选择 Source code (zip) 或 Code → Download ZIP。
3. 在解压后的文件夹中双击 **Install Agent Stage.command**。安装器打开终端，自动检查环境、准备游戏、连接 Codex、启动小窗。看到“安装完成”后返回 Codex，发送一个**新任务**。

不用输入命令。安装期间保留终端窗口；完成后可以关闭。安装脚本不使用 sudo 或请求管理员权限；macOS 自身的安全确认可能要求验证身份。安装中途不会替你重启 Codex、修改主题、关闭系统安全功能。安装后可删除下载的 ZIP 和解压目录。

DMG 是同一内容的另一种打包方式，不需要 ZIP 和 DMG 都下载。双击 DMG 后，在打开的磁盘中运行同名安装器；安装完成后可以推出磁盘。

## 首次打开被拦截

当前 Beta 未进行开发者签名和公证，首次下载可能有安全提示，这不属于“零点击”安装。只使用项目 Release 提供的文件，先核对校验和。确认来源可信后，按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，尝试打开文件，再到“系统设置 → 隐私与安全性 → 仍要打开”确认。不要全局关闭 Gatekeeper；如果系统提示恶意软件或文件损坏，先停止并反馈，不要强行绕过。

维护者会提供 SHA-256 文件。需要手动核对时，可在下载目录运行 `shasum -a 256 Agent-Stage-for-Codex.zip`，与 Release 中同名项比较。此步骤不要求普通用户为安装配置开发环境。

## 日常使用

Codex 窗口右下角使用独立 WebKit 小窗，任务开始且 Codex 位于前台时出现，结束或中断收起。切到其他应用、最小化/关闭 Codex 窗口或无法获取其位置时，小窗暂停并隐藏；返回后同一任务继续当前游戏，不重新抽取。窗口移动或缩放后会跟随其可见区域右下角，不再按鼠标所在屏幕的桌面角落定位。默认宽 520 像素，游戏区域保持原比例，另加 40px 顶部控制栏，常见总高度为 333 或 387 像素；Codex 窗口较小时自动缩小。右上角常驻随机与关闭图标，不遮挡游戏计分区。无需外部浏览器或 Codex 调试端口。点击关闭图标或在游戏中按 Esc，只收起本轮游戏，不会停止 Agent；下一轮仍可自动出现。Pause / Resume 控制之后是否出现。游戏库和静音设置仍在完整试玩页 `/codex-stage`。

源码根目录也提供 Install.command。源码安装复用已有 Node 22+；无法承诺每一种 Codex 都自带 Node，所以普通用户推荐完整 ZIP，里面有两种 Mac 架构的运行库。安装时不下载依赖，不要求 npm install。macOS 首次打开可能需要安全确认。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 Install Agent Stage.command | 确认下载完整 Release ZIP 并解压，不是源码包 |
| 安装后没出现小窗 | 回到 Codex 前台发送新任务；安装无法补发之前漏掉的开始事件 |
| 依然没出现 | 双击 Check Agent Stage.command，查看 NEEDS ATTENTION 项；公司策略禁用 hooks 时需联系管理员 |
| 检查正常，但旧会话不弹窗 | 先结束手头任务，退出并重新打开 Codex，再发新任务验证。服务在线、配置存在不代表当前会话已经发送开始事件；不要用试玩事件代替真实任务验收 |
| 提示 Node 不存在 | 很可能使用了源码包；换完整 Release，不需要单独安装 Node |
| 提示 Codex 不存在 | 将 Codex Desktop 正常安装到 Applications，并打开登录 |
| 提示 hooks.json 无效 | 保留原文件，先修复 JSON 或权限；安装器不会覆盖损坏的配置 |
| 4173 / 4282 端口被占用 | 先确认占用者；不要为了安装强制关闭不认识的进程 |
| 切到别的 App 游戏消失 | 正常行为，返回 Codex 后恢复 |
| 想暂时不玩 | 双击 Pause.command；Resume.command 恢复 |
| 更新版本 | 下载新 Release，重复运行安装器，无需先卸载 |
| 卸载 | 双击 Uninstall Agent Stage.command，仅移除本项目服务和 hooks；本地进度/媒体保留 |
| 下载目录已删除 | Finder 中“前往文件夹”输入 ~/.codex/agent-stage，检查和卸载入口在 macos/ 目录 |

反馈时提供版本、macOS 版本、芯片、游戏名和现象。只分享已脱敏的检查结果；不要上传 daemon.json、window.json、hooks 备份或任务日志。

Windows 用户请看 [Windows 网页试玩实验教程](WINDOWS_TESTING.zh-CN.md)，不要运行 Mac 的 .command 文件。

## 当前范围

- 100 款是不同作品总数：95 款编译游戏包 + 5 款本地页面适配器，现在都可在任务小窗中出现。
- 原来的 26 款仍然移除，不恢复。
- 默认从全部 100 款洗牌轮换，一轮内不重复；移到小窗右上角可点图标手动换游戏。随机模式下同款满 3 分钟后，在准备/结算状态、无按住输入且停手 5 秒时自动换一款。进行中的跳跃、瞄准、发射和工具事件均不触发强制切换；暂停、固定游戏或任务结束后不自动切换。
- 小窗不会被试玩页保存的游戏选择锁定。100 款包含实验性作品，不代表全部完成发布验收；7 款精选模式仍可在完整试玩页选择。
- 原生小窗是独立窗口，不宣称注入到新版 Codex 内部。
- 默认不依赖 CDP，默认静音，不抢走键盘焦点。
- 仅支持本地 macOS Codex；远端执行、组织禁用 hooks 等情形不承诺。

## 安装安全

先在临时目录准备和构建运行包，再替换自身目录。备份已有 hooks，仅增删自身命名条目；卸载不会删除其他 hooks。只对自身 hook 的确切内容记录信任，不禁用 Codex 的信任检查。

本机服务监听 127.0.0.1，事件接口需要随机 token。游戏只接触脱敏的开始/结束状态，不接触对话或工具内容。daemon.json / window.json 权限为 0600，不上传。用户视频和游戏进度不进入发行包。

窗口定位使用 macOS 前台应用标识、进程号和窗口几何信息，不读取 Codex 窗口标题、聊天、代码、辅助功能树或屏幕像素，不请求录屏或辅助功能权限。位置无法确认时隐藏，不退回全局悬浮。多个 Codex 窗口时跟随当前最前的可见普通窗口，并不绑定到某一聊天的内部面板。

## 推荐 GitHub 结构

公开仓库为 [lc345/codex-arcade](https://github.com/lc345/codex-arcade)，产品名为 Agent Stage。使用单仓库，首页突出“Agent 工作，你玩游戏”。

| 目录 | 职责 |
| --- | --- |
| 根目录 *.command | 安装、检查、暂停、恢复、卸载 |
| apps/codex-stage | 游戏、选集、宿主、资源和本地物理引擎 |
| packages/codex-stage | hooks、脱敏事件、本地服务、可选 Dock |
| macos | 原生小窗、启动服务、发行打包 |
| tools | 资源构建、隔离测试、发行文件白名单 |
| docs | 玩法、验证、贡献和许可证 |

白名单复制排除 .tools、node_modules、output、outputs、work、.env、日志和符号链接。官方 Node 运行库只进 Release，不进 Git 历史。发布前仍需人工审核素材来源、许可证和文档中的本机路径。

## 发布顺序

1. 本地安装后发送新任务，确认来自真实 Codex 的开始与结束，不是点试玩按钮。
2. 干净账户测试完整 ZIP 的安装、更新、暂停与卸载。
3. 审核素材许可和默认随机池；五个本地页面适配器已接入，但不为计数强行标正式。
4. 确认 GitHub 账号、仓库名和公开范围，创建仓库并推送检查过的文件。
5. 打 `agent-stage-v*` 标签，Actions 运行测试并发布 ZIP / DMG / SHA-256 文件。

尚未上传时，只能称“本地可安装包”，不能称已发布。
